1.1  PROJECT OVERVIEW
---------------------
CampusConnect is a full-stack web application developed for University of
Florida students to discover campus events, connect with student organizations,
and RSVP — all in one centralized place. The motivation behind the project is
a common student pain point: information about campus activities is scattered
across email listservs, physical flyers, and disconnected social media
accounts, making it difficult for students to stay informed and engaged.

CampusConnect addresses this by providing a single, clean interface where
students can browse upcoming events, search and filter by keyword or date
range, register for events with a single click, and — for administrators —
create, edit, and delete event listings. The system uses JWT-based
authentication to differentiate three privilege levels: user, organization,
and admin.

NON-FUNCTIONAL REQUIREMENTS
----------------------------
- Performance:     All API responses complete in under 500 ms under normal
                   load. Client-side search and filtering avoid network
                   round-trips on every keystroke.

- Security:        Passwords are never stored in plaintext. All sensitive
                   routes require a valid JWT. SQL queries use parameterized
                   values to prevent injection. React's JSX escapes all
                   rendered output, preventing XSS.

- Usability:       The interface is operable without a manual. Toast
                   notifications confirm every action (success in green,
                   error in red). RSVP state is updated optimistically
                   without requiring a page reload.

- Maintainability: Frontend and backend are independently runnable with a
                   clean API boundary. A global CSS custom-property design
                   system defines the UF brand palette in one location.

- Portability:     Docker Compose enables one-command deployment on any
                   host with Docker installed. All secrets are externalized
                   via environment variables.

1.5  DATABASE SCHEMA
--------------------

  -- Users table
  CREATE TABLE users (
      id            SERIAL PRIMARY KEY,
      email         TEXT UNIQUE NOT NULL,
      password_hash TEXT NOT NULL,
      name          TEXT,
      privilege     TEXT DEFAULT 'user'   -- 'user' | 'organization' | 'admin'
  );

  -- Events table
  CREATE TABLE events (
      id          SERIAL PRIMARY KEY,
      title       TEXT,
      date        DATE,
      time        TIME,
      location    TEXT,
      description TEXT
  );

  -- RSVPs (many-to-many join table)
  CREATE TABLE event_signups (
      id       SERIAL PRIMARY KEY,
      user_id  INTEGER REFERENCES users(id)  ON DELETE CASCADE,
      event_id INTEGER REFERENCES events(id) ON DELETE CASCADE,
      UNIQUE(user_id, event_id)    -- prevents duplicate RSVPs
  );

2.2  SCRUM PROCESS & SPRINT HISTORY
-------------------------------------
The team adopted a lightweight Scrum framework with Daniel Gleeson serving as
Scrum Master and Frank Ascencio as Product Manager / Product Owner. Work was
organized into two-week sprints. The product backlog was maintained as a
prioritized list of user stories, and each sprint began with planning and
ended with a review and retrospective.

  Sprint 1 — Goal: Project scaffolding & basic data display
    Deliverables:
    - Vite + React frontend initialized
    - Express server running
    - PostgreSQL tables created (users, events)
    - Events fetched from database and displayed on the home page

  Sprint 2 — Goal: Authentication & routing
    Deliverables:
    - JWT login / signup endpoints
    - AuthContext provider for global user state
    - React Router v6 integration: Home, Login, SignUp, About, Organizations
    - Session persistence via localStorage (token survives page refresh)

  Sprint 3 — Goal: Admin CRUD & UI polish
    Deliverables:
    - Event creation modal
    - Event edit modal (React Portal fix for CSS stacking context / click
      interception issue)
    - Delete event button (orange styling)
    - CSS design system with UF brand colors (--gator-blue, --gator-orange)
    - Navbar routing with React Router Link components

  Sprint 4 — Goal: Search, filter & RSVP
    Deliverables:
    - Live search bar (filters as user types)
    - Date-range filter dropdown (This Week / This Month)
    - RSVP / Cancel RSVP with optimistic UI updates and live attendee count
    - Toast notifications for all user actions
    - Docker Compose deployment configuration
    - README finalized

    400  Bad Request (missing required fields)
    401  Unauthorized (invalid credentials or missing token)
    404  Not Found (user or event does not exist)
    409  Conflict (duplicate email or duplicate RSVP)
    500  Internal Server Error (database error)


3.3  INSTALLATION GUIDE
------------------------

PREREQUISITES
  - Node.js v20 or later   (verify: node --version)
  - npm v9+  (bundled with Node)
  - A Neon PostgreSQL project — create a free account at neon.tech and
    copy the connection string from the Neon dashboard
  - Docker Desktop (optional — only required for containerized deployment)

LOCAL DEVELOPMENT (RECOMMENDED)

  # 1. Clone the repository
  git clone https://github.com/Gleeson-Daniel/CampusConnect.git
  cd CampusConnect

  # 2. Create the environment file
  #    Create server/.env and fill in DATABASE_URL and JWT_SECRET
  #    (see Section 3.4 for the exact format)

  # 3. Install all dependencies (root + client + server)
  npm install

  # 4. Start both frontend and backend together
  npm run dev
  #   Frontend  ->  http://localhost:5173
  #   Backend   ->  http://localhost:3000

DOCKER DEPLOYMENT

  # Build and start containers
  docker compose up --build

  # Stop containers
  docker compose down

  NOTE: On Windows, running 'docker compose up' may interfere with localhost
  DNS resolution. If the browser shows ERR_CONNECTION_RESET after a Docker
  session, run 'docker compose down' and switch back to 'npm run dev' for
  local development.

CREATING AN ADMIN ACCOUNT

  1. Register a new account via the Sign Up page.
  2. Find the user's id in the Neon SQL editor:
       SELECT id, email FROM users;
  3. Send a POST to /api/assign-privilege with body:
       { "userId": <id>, "privilege": "admin" }
     (e.g., via Postman, curl, or the browser dev tools)
  4. The user must log out and log back in for the new privilege to
     take effect in their JWT.

4.2  SOFTWARE QUALITY ATTRIBUTES
----------------------------------

SECURITY
--------
Passwords are hashed with bcrypt using 10 salt rounds before storage —
plaintext passwords are never persisted at any layer. JWTs are signed with a
secret key and carry a 7-day expiration; the server validates the signature on
every protected request via the authMiddleware. SQL queries use parameterized
values throughout the Express server (pool.query(sql, [values])), eliminating
SQL injection risk. React's JSX automatically escapes all rendered values,
protecting against stored cross-site scripting (XSS).

The primary outstanding security gap is that admin mutation endpoints
(/api/create-event, /api/update-event, /api/delete-event) do not yet verify
server-side that the caller holds the 'admin' privilege. This is the highest-
priority item before any public deployment.

USABILITY
---------
Every user action that modifies server state (RSVP, cancel RSVP, create /
edit / delete event) is confirmed with a color-coded toast notification from
react-toastify — green for success, red for failure — positioned in the top-
right corner and auto-dismissing. Attendee counts update optimistically in
the UI immediately after a successful HTTP response, without requiring a page
reload. The search bar filters results as the user types, with no Submit
button. Modal dialogs are dismissible by clicking the overlay background or
the × button in the top-right corner of the modal.

The UF brand color palette (blue #003087, orange #FA4616) is applied
consistently through CSS custom properties, giving the application a cohesive,
recognizable feel for University of Florida students.

RELIABILITY
-----------
Database-level UNIQUE(user_id, event_id) constraints prevent duplicate RSVPs
regardless of race conditions or repeated client requests. Cascade delete on
event_signups ensures that removing an event automatically cleans up all
associated RSVP records, preventing orphaned rows. The Express server uses
try/catch blocks on all async route handlers, returning structured JSON error
responses with appropriate HTTP status codes rather than crashing on unexpected
errors. The event_signups table is created at server startup with CREATE TABLE
IF NOT EXISTS, ensuring the schema is always present without requiring a
separate migration step.

MAINTAINABILITY
---------------
The frontend and backend are independently runnable services with a clean API
boundary (HTTP + JSON). Neither side imports code from the other; all
communication is through documented endpoints. React components are organized
by concern:

  pages/         Home, Login, SignUp, About, Organizations
  components/    Navbar, EventList, SearchBar, modal, AuthContext, AuthGate

A global CSS custom-property design system defines the UF brand palette in a
single location, making brand updates a one-file change. The root package.json
uses 'concurrently' to start both services with a single 'npm run dev' command,
reducing developer onboarding friction.

PORTABILITY
-----------
Docker Compose provides a fully self-contained deployment unit. A single
'docker compose up --build' command builds and starts both the frontend and
backend containers on any host with Docker installed. Environment variables
externalize all host-specific and secret configuration, keeping the codebase
itself environment-agnostic. The frontend Dockerfile serves the Vite dev
server inside a container on port 5173; the backend Dockerfile runs Node.js
on port 3000; a shared bridge network (campusconnect-network) allows the two
services to communicate. The backend includes a health check endpoint
(/health) that Docker Compose polls before starting the frontend.

PERFORMANCE
-----------
Event search and date filtering are implemented entirely client-side, meaning
every keystroke does not generate a network request. Only the initial page
load and explicit actions (RSVP, create/edit/delete) trigger API calls.
RSVPs are applied optimistically: the button state and attendee count update
immediately in the React state upon receiving a successful HTTP response;
a full event list refetch is avoided. The PostgreSQL query for event listing
uses a single LEFT JOIN with COUNT aggregation to retrieve events and their
attendee counts in one database round trip:

  SELECT e.*, COUNT(es.id)::int AS rsvp_count
  FROM events e
  LEFT JOIN event_signups es ON e.id = es.event_id
  GROUP BY e.id
  ORDER BY e.id
